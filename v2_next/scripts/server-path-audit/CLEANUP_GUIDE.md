2026-09-15 사용자의 “정리 승인 필요없는건 과감히 삭제”에 따라, 아래의 바이트가

## 삭제 범위

대상 부모는 하나로 고정돼 있습니다.

`C:\Users\user\Desktop\SmartFactory_Archive\pre_v1020_quarantine_20260813_092302`

이 안의 **완전한 압축 해제 폴더**만 검사합니다. 같은 부모의 직계 ZIP을 보존하면서,
폴더에 들어 있는 모든 파일의 상대경로·길이·SHA256이 그 ZIP의 정확한 entry로
복원됨을 확인해야 삭제합니다. ZIP root 또는 같은 이름의 top 폴더 배치만 인정합니다.
일부 파일만 중복이면 폴더 전체를 보존합니다. 폴더 안에 든 nested ZIP도 동일 조건을
만족해야 하며, 삭제 후보 안의 ZIP을 복구 원본으로 사용하지 않습니다.

다음은 삭제하지 않습니다.

- 직계 파일 89개 전부: 보존 ZIP 33개, JSON, 해시 파일, 단독 스크립트 등.
- 과거 설치 전 백업/설정 폴더 4개와 v1.0.19 R4 closeout 연결 폴더.
- 보존 문서·서비스·작업·바로가기 등에서 참조가 발견된 후보와 그 연결 후보.
- ZIP 전체 일치를 확인하지 못한 폴더, 설정/백업, ADS가 발견되거나 검사가 실패한 후보.
- 기존 manifest/검증 영수증 6개. 과거 내용을 수정하거나 새 PASS로 바꾸지 않습니다.
- 이 부모 밖의 운영 데이터, 현재 설치본, v1.0.25 증거·복구 설치본, v1.0.26 후보.

과거의 837MB 후보 추정치는 이 삭제 범위가 아닙니다. ZIP/참조 검사 전 상한은
42폴더·386파일·512,547,589바이트이며, 실제 삭제 수/용량은 서버에서 더 줄어들 수
있습니다. 안전한 중복이 없으면 `NO_ELIGIBLE_DUPLICATE_FOLDERS`로 끝납니다.

## 실행과 기록

1. ZIP과 `.sha256.txt`를 서버의 기존 전송 폴더 `C:\Users\user\Desktop\SmartFactory`에 복사합니다.
2. 개발 PC에서 제공한 `RUN_CLEANUP.txt` 전체를 관리자 x64 Windows PowerShell 5.1에 붙여넣습니다.
3. 해시 검증 후 도우미는 `C:\ProgramData\SFLOps\tmp\q20-helper-<id>`에 생성됩니다.
4. 원본 558파일 재검증 → ZIP 재검증 → 보존 참조 검사 → 삭제 목록 출력 순서로 진행합니다.
5. 삭제 전에 정확한 PLAN을 `C:\ProgramData\SFLOps\inventory\q20-<id>\cleanup.jsonl`에 기록합니다.
6. 파일별 INTENT를 디스크에 기록한 후 동일 검증 handle로 삭제하고, DELETED를 기록합니다.
7. 남겨 둔 파일을 다시 해시 검사하고 최종 개수·크기·기록 경로·기록 SHA256을 출력합니다.

서버 앱 종료·재시작, 설치, 롤백, 카메라 요청, 새 관측, 네트워크 전송은 없습니다.
직접적인 삭제 작업은 휴지통을 거치지 않습니다. 상위 폴더 전체의 재귀 삭제는 없습니다.
현재 실행 환경에서 사용 중이거나 내용이 바뀐 파일을 강제로 지우지 않습니다.

## 중단과 복구

어떤 예외든 자동 재실행·정리·복원을 하지 않습니다. 실패 이전의 일부 폴더/파일은
이미 삭제됐을 수 있습니다. 콘솔과 `cleanup.jsonl`을 함께 보존해 전달하십시오.
INTENT는 있는데 DELETED가 없는 경우에는 실제 경로를 별도 확인해야 합니다.
원래 manifest가 삭제 전 목록이므로 완료/부분 완료 후 같은 도우미를 재실행하면
원본 불일치로 멈추는 것이 의도된 동작입니다.

삭제한 **주 데이터 바이트와 상대경로**는 PLAN의 `zip`/`zip_sha256`/`zip_entry`로
추적할 수 있습니다. 필요 시 해당 entry만 원래 위치에 복원하고 해시를 대조해야 합니다.
ZIP 전체를 무조건 풀거나 복구 스크립트를 실행하지 마십시오. ACL·생성시각까지의 완전한
파일시스템 복원 또는 현재 운영 데이터의 백업을 보장하는 것은 아닙니다.

## 검증 범위와 한계

- Windows PowerShell 5.1 x64 합성 파일로 경로/ZIP/참조/handle 삭제/중간 실패를 시험했습니다.
- 실제 서버 ZIP의 내용과 최종 삭제량, 관리자 ACL 생성 및 전체 서버 실행은 현장 실행 때 확인합니다.
- 참조 조사는 이전 점검과 같은 한정된 경로/깊이의 문자 검색입니다. 다른 사용자·드라이브,
  간접/인코딩된 경로, COM 작업, 모든 열려 있는 handle의 사용 관계를 완전히 증명하지 않습니다.
- 알려진 Start Menu 호환 junction 2개만 참조 열거 예외로 남기며, 새 reparse는 중단합니다.
- 상대적으로 작은 격리 자료 약 1.08GB와 ZIP을 읽는 동안 디스크 I/O 부하는 있습니다.
- 파일 내용은 콘솔에 노출하지 않습니다. 정리 기록에는 사내 경로/증거 메타데이터가 있으므로 공개하지 마십시오.
- 개발 저장소의 로컬 준비물이며 커밋·PR·서버 운영 승인이 아닙니다.

핸들 삭제는 Microsoft의 [SetFileInformationByHandle 문서](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)
계약에 따라 DELETE 접근을 얻은 검증 handle에 FileDispositionInfo를 설정합니다.
