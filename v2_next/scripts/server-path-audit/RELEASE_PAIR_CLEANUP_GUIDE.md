# v1.0.19 중복 사본 2차 정리

## 삭제 범위

사용자가 승인한 구버전 배포 폴더 두 개의 중복 사본만 정리한다.
고정 부모 경로:

```text
C:\Users\user\Desktop\SmartFactory_Archive\pre_v1020_quarantine_20260813_092302
```

- 삭제 쪽: `release_private_unsigned_v1_0_19_0c1ad4f_20260810_R1`
- 보존 쪽: `release_private_unsigned_v1_0_19_0c1ad4f_20260810_R2_clean`
- 두 폴더 각각 23파일 중 같은 상대경로·길이·SHA256의 **R1 사본 22파일**만 영구 삭제한다.
- 예상 삭제량: **157,989,430 bytes (약 150.7 MiB)**.
- **디렉터리는 하나도 삭제하지 않는다.** R2_clean 23파일 전체와 R1 고유 JSON을 남긴다.
- 현재 제품, 설정, 수집 데이터, 백업, v1.0.25/26 자료와 다른 구버전 폴더는 삭제하지 않는다.

보존하는 고유 파일:

```text
R1\server_kit\server_check_before_v1019_0c1ad4f_install_20260810_075959.json
R2_clean\server_kit\server_check_before_v1019_0c1ad4f_install_20260810_105635.json
```

위 R1/R2_clean 표기는 긴 실제 폴더명의 약칭이다. 도우미는 실제 이름과 두 JSON의
개별 해시를 고정한다. 원본 JSON·과거 manifest·1차 삭제 기록은 수정하지 않는다.

## 선행 완료 기록

1차 삭제 기록은 다음 경로 및 해시와 정확히 같아야 한다.

```text
C:\ProgramData\SFLOps\inventory\q20-20260915-103611-1597b3d9\cleanup.jsonl
79A9C3534C2CB4DB56C865391516152582FB4A8006EE97F265889D766561EBD5
```

도우미는 원본 558파일 manifest에서 1차 완료된 88파일을 제외해 현재 470파일을
재구성한다. 이전 도우미를 다시 실행하지 않는다. 완료 후에는 448 원본 파일과
6개 메타데이터 파일이 남아야 한다. 서버 전체 정리 완료는 아니다.

## 실행 방법

1. 새 `v1019-release-pair-cleanup-ready-r1.zip`과 `.sha256.txt`를 서버의
   `C:\Users\user\Desktop\SmartFactory`로 옮긴다. 과거 ZIP을 덮어쓰지 않는다.
2. 함께 제공한 `RUN_RELEASE_PAIR_CLEANUP.txt`의 전체 내용을 관리자 권한
   **64비트 Windows PowerShell 5.1**에 붙여 넣는다. Markdown 기호는 붙이지 않는다.
3. ZIP을 수동으로 압축 해제하거나 안의 오래된 설치본/도구를 실행하지 않는다.
4. 1/6부터 6/6까지 안내 후 COMPLETE와 JOURNAL SHA256이 표시되면 전체 출력을 전달한다.

승인된 실행 launcher는 `-Execute`를 명시한다. 추가 YES 입력은 없다.
도우미 자체를 인수 없이 실행하면 점검 및 계획 출력만 한다.
앱 종료·재시작·설치·관측·제품 API 조회는 하지 않는다.

## 검증과 중단 조건

- 외부 고정 ZIP 해시/길이를 확인하고 검증된 바이트만 `SFLOps\tmp`의 새 보호 폴더에 둔다.
- 해시가 고정된 원본 메타데이터 6개와 1차 완료 journal을 읽기 잠금한다.
- 전체 잔존 목록의 경로·파일 종류·크기를 확인하고, **대상 두 폴더의 46파일을 재해시**한다.
- 경로 바꿔치기, reparse, hard link, 보존되지 않는 ADS, 쓰기/삭제 잠금 충돌은 거부한다.
- 프로세스·서비스·시작 항목·작업과 지정 Desktop/Start Menu/기존 SFL 폴더의
  제한된 텍스트·바로가기 참조를 점검한다. 남길 문서에서 R1 참조가 나오면 고유 JSON이라도 HOLD한다.
- 보존 R2 파일을 잠근 상태에서 R1 대상 **22개 모두 삭제 접근 핸들을 확보·재검증한 다음** 삭제를 시작한다.
- 파일별 DELETE_INTENT를 디스크에 기록한 뒤 같은 검증 핸들로 삭제하고 DELETED를 기록한다.
- 마지막에 보존한 24파일을 재해시하고 전체 잔존 경로/크기 및 디렉터리 보존을 확인한다.

참조 검색은 지정 범위·깊이·텍스트 크기 한정이며, 다른 사용자/드라이브, 인코딩된
참조, COM 등 모든 사용 경로의 부재를 증명하지 않는다. 대상 외 나머지 파일 전체의
해시를 전후 재검증하는 작업도 아니다. 제품 런타임 건강 점검을 대신하지 않는다.
잠금·권한·디스크·보안 프로그램 오류로 일부 파일 삭제 후 HOLD될 수 있다.

## 기록과 복구

새 기록 경로:

```text
C:\ProgramData\SFLOps\inventory\q19-pair-<시간>-<식별자>\cleanup.jsonl
```

PLAN/DELETE_INTENT에는 각 `relative_path`와 대응하는 R2 `retained_relative_path`,
길이·SHA256이 들어 있다. 삭제 사본의 **주 데이터 바이트**는 R2에서 복원 가능하다.
휴지통 복구가 아니며 ACL·생성 시간 등 모든 메타데이터 복원을 보장하지 않는다.
이것은 앱 버전 롤백이나 현재 운영 데이터 백업이 아니다.

HOLD가 나오면 모든 출력·새 기록·남아 있는 R2 파일을 보존한다. 자동 재실행·복구·
추가 삭제를 하지 않는다. INTENT만 남은 경우는 실제 경로를 다시 확인해야 하며,
완료 이벤트가 없다는 이유로 삭제가 전혀 없었다고 판단하면 안 된다.
성공한 2차 도우미도 다시 실행하지 않는다. R1은 일부 파일이 제거된 과거 폴더이므로 실행하지 않는다.

## 검증 수준

개발 PC의 Windows PowerShell 5.1에서 해시 결합된 전송 manifest/1차 journal과
작은 합성 파일을 사용해 계획, 범위, 삭제 접근 잠금, 변조·ADS·기록 실패 중단을 시험한다.
실제 서버 2차 삭제는 배포 전 실행하지 않는다. 제품 코드 변경·DB 마이그레이션은 없다.
