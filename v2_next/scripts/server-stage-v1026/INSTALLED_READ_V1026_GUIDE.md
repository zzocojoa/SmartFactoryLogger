# v1.0.26 설치 파일 읽기 전용 확인

앱을 켠 상태로 실행한다. 설치·종료·재시작·설정 재확인 갱신·Canary는 수행하지 않는다.
관리자 권한의 64비트 Windows PowerShell 5.1과 기존 서버 사용자 계정이 필요하다.
도우미는 서버 사용자 SID에 결합돼 있어 개발 PC에서 실행하면 진행하지 않는다.

## 실행

1. `read-installed-v1026.ps1`과 `.sha256.txt`를 서버의
   `C:\Users\user\Desktop\SmartFactory`로 복사한다.
2. 제공된 `RUN_ON_SERVER.txt` 안의 짧은 명령만 관리자 Windows PowerShell에 붙여넣는다.
   명령에 독립적으로 기록된 SHA256과 읽기 잠금된 도우미 바이트가 일치해야 실행된다.
   별도 ExecutionPolicy 변경이나 ZIP 압축 해제는 필요 없다.
3. 끝에 `[SEND FILE]`로 표시된 **result.json 또는 hold.json 하나**를 파일로 전달한다.
   긴 콘솔 출력을 전체 선택해서 복사할 필요가 없다.

## 범위

- 보호된 기존 stage의 릴리스 identity와 manifest를 외부 고정 해시로 검증한다.
- 설치된 payload 1,645개와 고정된 제거 프로그램 1개를 길이·SHA256·집합으로 대조한다.
- 일반 사용자 앱·백엔드의 실행 경로, 부모 관계, 세션·SID·권한, PID·시작 시각과
  포트 소유권을 점검 전후 비교한다. 기존 HOLD를 설치 성공 영수증으로 바꾸지 않는다.
- config.ini는 짧은 공유 읽기로 설치 전 해시와 비교한다.
- 로컬 health를 두 번, 설정 상태와 오류 집계를 각 한 번 읽는다.
  이미지 조회나 장비 설정 요청은 직접 발행하지 않는다. 앱의 정상 요청 로그는 기록될 수 있다.
- 서버에서 새로 쓰는 파일은 `C:\ProgramData\SFLOps\runs\v1026-tree-read-<시각>-<GUID>`의
  선별된 결과와 해시뿐이다. 새 결과 폴더에만 관리자/SYSTEM 전체 권한과 고정된
  서버 작업자 SID 읽기 권한을 준다. 작업자 쓰기는 허용하지 않으며 기존 부모 폴더의
  ACL은 변경하지 않는다. `[SEND FILE]` 경로의 파일을 일반 탐색기에서도 읽을 수 있다.
  기존 증거·설정·설치 파일은 덮어쓰지 않는다.
  Add-Type에 따른 시스템 임시 컴파일 파일 생성은 제품 파일 수정과 별개다.

## 결과와 제한

`V1026_INSTALLED_TREE_VERIFIED_OPERATIONAL_REVIEW_PENDING`은 파일 일치 확인만 뜻한다.
v1.0.20의 과거 설정 확인 지문이 남아 있는 문제는 별도 상태로 출력하며 갱신하지 않는다.
실제 장비 설정 대조와 운영자 확인, 정상 종료가 필요한 갱신 절차는 별도 단계다.

약 561 MB의 파일을 순차적으로 읽으므로 디스크 I/O와 CPU 부하가 잠깐 생긴다.
300초 예산은 파일·디렉터리 사이에 확인하며, 단일 OS 디스크 읽기를 강제 취소하는
하드 타임아웃은 아니다. 업데이트·설정 편집과 동시에 실행하지 않는다.

원자적 파일시스템 스냅샷이나 실행 메모리 검증이 아니며, 적대적 경로 교체 경쟁을
완전히 방어하지 않는다. 재분석 지점은 거부하지만 ADS·빈 디렉터리·hardlink 수는
검증하지 않는다. 변경 후 원복 같은 중간 상태와 현재 장비 설정의 진실성을 증명하지 않는다.
연속 영상 갱신, UI 프레임 성능, CSV 전체 복구 가능성, 장기 운영 승인은 확인하지 않는다.

HOLD가 나오면 결과와 생성 폴더를 보존하고 자동 재시도·삭제·롤백하지 않는다.
기존 최소 백업과 복구 설치본은 유지한다. 최소 백업에는 누적 CSV/이미지/fact 데이터가
포함되지 않는다. 도우미 결함은 새 버전으로 준비하며 과거 도우미를 현장에서 수정하지 않는다.

## 개발 검증 경계

로컬 시험은 native PowerShell 5.1에서 함수 AST만 가져와 실행한다. 서버 main은 실행하지
않는다. 실제 추출 릴리스 바이트 및 합성 변조/경로/상태 fixture를 확인하지만, 서버 ACL
생성, 실제 프로세스 부모 관계, 실제 로컬 API의 연속성은 서버 실행 전에는 확인할 수 없다.
