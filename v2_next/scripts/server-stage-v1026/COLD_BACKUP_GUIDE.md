# v1.0.25 종료·백업·파일 복원 검증

## 준비와 실행은 별개

이 패키지는 **실행 준비본**이다. 실제 서버의 정상 종료·파일 복사 실행은 점검 시간을
확보하고 별도로 승인한 뒤에만 한다. v1.0.26 설치, 롤백, 재시작, 오류 큐 삭제는 포함하지 않는다.
현재 v1.0.25의 main 6728 / backend 7620과 시작 시각, 제품 commit 및 설정이
달라졌으면 자동으로 새 기준을 받아들이지 않고 HOLD한다.

기본 실행에는 조회/복사가 없다. `-Execute`와 `BACKUP V1.0.25` 입력이 모두 필요하다.
제공된 실행 안내의 외부 SHA256을 검증한 뒤 사용한다. ZIP 안의 sidecar만 믿고 실행하지 않는다.

## 복사할 대상

다음 **세 폴더 전체**를 포함한다. 숨김 파일, 이미지 하위 폴더, 빈 폴더도 포함하며
확장자별 제외나 기존 파일 삭제가 없다.

| 백업 별칭 | 서버 원본 |
| --- | --- |
| r0 | `C:\Users\user\AppData\Roaming\SmartFactoryLogger` |
| r1 | `C:\Users\user\AppData\Roaming\smart-factory-logger-v2` |
| r2 | `C:\Users\user\AppData\Local\Programs\smart-factory-logger-v2` |

설치 폴더까지 포함하는 것은 portable/fallback 데이터와 이전 설치 파일을 보존하기
위함이다. 다른 위치의 모든 런타임 경로를 확인했다는 뜻은 아니다. 설정상 로그·snapshot·
캡처 경로가 이전 확인값과 다르면 진행하지 않는다.

## 단계별 실행 화면

1. 현재 프로세스·설정·복구 EXE·Electron 시작 세션을 확인한다.
2. 세 폴더를 **메타데이터만 재귀 열거**하여 전체 파일 수·논리 크기와 대상 경로 길이를 확인한다.
   전체 이미지가 포함되어 시간이 걸릴 수 있다. 아직 앱을 닫거나 백업 폴더를 만들지 않는다.
3. 용량과 새 목적지 `C:\ProgramData\SFL26B-<임의 식별자>`를 표시한다.
   `BACKUP V1.0.25`를 입력한 뒤 **닫으라는 안내가 나오면** 앱 창의 X로 정상 종료한다.
   작업 관리자, taskkill, Stop-Process는 사용하지 않는다.
4. 기존 프로세스 핸들의 exit 0, 이번 세션의 non-forced 정상 종료 로그, 새 image fact
   closeout 파일과 실제 fact 해시를 확인하고 정지 상태에서 용량을 다시 계산한다.
5. `<새 목적지>\backup`에 원본을 복사하고 파일별 SHA256·원래 경로/메타데이터/SDDL을
   `<새 목적지>\files.manifest.tsv`에 기록한다.
6. 백업 파일을 다시 읽고 해시를 검사하면서 `<새 목적지>\restore`에 복원 시험본을 만든다.
7. 복원 시험본과 원본을 각각 다시 읽어 해시를 비교하고 파일·폴더 구성의 누락/추가를 검사한다.
8. 모두 통과한 경우에만 `result.json`과 `.sha256.txt`를 새로 기록한다.

각 긴 단계에는 경과 시간·파일 수·처리 바이트·단계 진행률/남은 시간 추정치를 표시한다.
처리속도가 없는 초기 구간과 열거 단계에서는 남은 시간을 알 수 없다. 단계 추정이지 전체
중단 시간 약속이 아니다. 개별 막힌 OS 호출을 강제로 선점 중단하지는 못한다.

**완료 후에도 앱은 정지 상태다.** 마지막 YES는 없다. `result.json`, 해시와 콘솔 출력을
비공개로 전달하고 다음 설치/재시작 결정을 기다린다. 백업/프로필 원본은 첨부하지 않는다.

## 용량과 중단 시간

ZIP 압축을 사용하지 않는다. 대형 파일을 스트리밍 처리하며 원본과 별도로 백업본·복원
시험본 두 벌을 보관한다. 예비 필요 공간은 `원본 바이트 × 2.1 + 항목 수 × 16KiB + 10GiB`다.
메타데이터·할당 비용의 보수적 추정이며 디스크 예약/할당량 보장은 아니다. 디렉터리·파일·
manifest 생성과 진행 중에도 여유 공간을 확인한다. 다른 프로세스의 공간 사용 등으로
정지 후에도 HOLD가 발생할 수 있다.

점검 때 C: 여유는 109.84GiB였지만 전체 이미지 크기는 아직 미확인이다. 공간이 부족하면
첫 번째 검사는 앱 종료 안내 전에 멈춘다. 다른 파일을 지우거나 임의 드라이브로 우회하지 않는다.
필요하면 별도 목적지에 맞춘 준비를 다시 한다.

백업과 여러 번의 재읽기가 끝날 때까지 **수십 분 이상** 중단될 수 있다. 중간에 사용자가
앱을 다시 실행하면 HOLD한다. 점검 시간 확보 없이 실행하지 않는다.

## 원본 보존과 한계

- 새 목적지는 관리자/SYSTEM 전용으로 생성한다. 원래 경로에 복원하거나 기존 백업을
  덮어쓰지 않는다. 실패 시 부분 파일도 자동 삭제하지 않는다.
- 원본 파일은 읽기만 한다. 정상 종료 자체가 수행하는 CSV/fact 마무리 기록은 발생한다.
  도우미는 앱 종료 API나 강제 종료를 호출하지 않는다. 기존 앱에는 장시간 종료 실패 시
  자체 강제 종료 시도가 있으므로 non-forced 종료 증거가 없으면 통과하지 않는다.
- 프로필에는 API 키/쿠키가 있을 수 있다. 원문 내용과 임의 파일명을 콘솔에 출력하지
  않지만 백업 자체는 민감정보를 포함한다. 보호 ACL은 암호화가 아니다.
- 같은 C: 볼륨의 복사다. **디스크 고장·랜섬웨어 대비 외부 백업은 아니다.**
- 대체 데이터 스트림, reparse point, EFS, sparse/offline 파일 등 지원하지 않는 대상은
  조용히 제외하지 않고 HOLD한다. Native handle 기반 경로 고정/VSS를 사용하지 않아
  적대적인 동시 경로 교체를 방어한다고 주장하지 않는다. 프로세스 감시는 주기적이다.
- 원본 시각·속성·보안 설명자(SDDL)는 기록한다. 시험 복원본에 원래 ACL/소유권·속성·
  시각을 적용하지 않는다. 하드링크 관계/감사 ACL/SACL/파일시스템 전체를 복원하는 도구가 아니다.
- 파일의 복원·해시 일치는 **앱 재기동 성공, CSV 업무 의미/모든 행의 무결성, Electron
  프로필 다운그레이드 호환성, 설치 준비 완료**를 뜻하지 않는다. 과거 오류/누락도 복구하지 않는다.

## HOLD가 나오면

출력과 새 목적지 전체를 보존한다. 자동 재실행·정리·강제 종료·재시작·설치·롤백을 하지 않는다.
이미 앱이 닫혔다면 정지 상태로 결과를 전달한다. 일부 복사본을 완료 백업으로 사용하지 않는다.
`result.json`과 sidecar 및 manifest hash가 최종 완료 기준이며 `intent.json`/`hold.json`은
완료 증거가 아니다. 그 자체로 설치 승인을 제공하지도 않는다.

이후 실제 복구가 필요하면 업그레이드 이후 생긴 데이터부터 별도로 보존하고, 검토된 복구
설치본과 원래 profile/data를 연결한 복구 도우미를 사용한다. 수동 덮어쓰기로 복구하지 않는다.

## 구현 근거

파일·디렉터리 API는 Windows PowerShell 5.1의 .NET Framework를 사용한다.
서버에서 컴파일하지 않고 해시 검증된 DLL 바이트를 메모리에 로드한다.
새 보호 폴더는 보안 설명자를 받아 생성하는 API를 사용한다.
[Microsoft Directory.CreateDirectory 문서](https://learn.microsoft.com/en-us/dotnet/api/system.io.directory.createdirectory?view=netframework-4.8.1)
