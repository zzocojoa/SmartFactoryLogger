# V2.0 (웹 기술) 상용 배포 가이드: 2025 실무 표준

`작성일: 2025-12-31`
`주제: 개발용 PC(Windows)에서 만든 Web Stack 프로그램을 현장 PC(Windows)에 이식하는 법`

## 1. 질문에 대한 직답

**Q: "이것도 빌드를 하는 것인가?"** **A: "네, 무조건 합니다. 심지어 V1보다 더
철저하게 합니다."**

웹 기술(React, Vue)는 소스 코드를 그대로 배포하지 않습니다. 공장 PC 인터넷이 안
되어도 더블 클릭 한 번으로 설치되도록 **"설치 파일(.exe / .msi)"로 만드는
과정(패키징/빌드)**이 필수입니다.

---

## 2. 2025년 실무 프로세스 (Build & Deploy Workflow)

개발자 PC에서 인터넷이 없는 현장 PC까지 가는 표준 여정을 정리해 드립니다.

### Step 1. 빌드 (Build) - 개발자 PC에서 수행

우리가 작성한 수천 개의 코드 파일(React, Python, CSS 등)을 **하나의 설치
파일**로 압축하는 과정입니다.

1. **프론트엔드 빌드**: `npm run build`
   - React 소스(사람이 읽는 코드)를 브라우저가 이해하는 최적화된
     파일(HTML/JS/CSS)로 변환합니다.
2. **백엔드 패키징**: `pyinstaller` (V1과 동일)
   - Python 로직을 실행 파일로 만듭니다.
3. **통합 패키징 (Bundling)**: `PyInstaller` (OneDir 모드)
   - 현재 단계에서는 `electron-builder` 대신, 백엔드(`SmartFactoryBackend`)가
     프론트엔드 정적 파일(`dist`)을 내장/서빙하는 구조로 배포합니다.
   - 결과물: `dist/SmartFactoryBackend` 폴더 (내부에 `frontend/dist` 포함 필요)

### Step 2. 이식 (Transfer) - USB 또는 사내망 이용

- **결과물**: `SmartFactorySetup_v2.0.0.exe` (약 100MB~200MB 예상)
- 이 파일 하나만 USB에 담아서 현장으로 가져갑니다.
- 소스 코드 폴더를 통째로 복사하는 방식(X) -> **설치 파일만 복사하는 방식(O)**

### Step 3. 배포 (Deployment) - 현장 PC에서 수행

1. 현장 PC 바탕화면에 `SmartFactorySetup_v2.0.0.exe`를 놓습니다.
2. **더블 클릭**합니다.
3. 카카오톡이나 엑셀 설치하듯이 **"설치하시겠습니까? -> 다음 -> 완료"** 과정이
   진행됩니다.
4. 바탕화면에 아이콘이 생기고, 실행하면 깔끔하게 프로그램이 뜹니다.

## 3. 왜 이렇게 하나요? (소스 복사 vs 빌드 배포)

| 구분         | 소스 코드 통째로 복사 (옛날 방식)                       | 설치 파일 빌드 배포 (2025 표준)                               |
| :----------- | :------------------------------------------------------ | :------------------------------------------------------------ |
| **보안**     | 현장 PC에서 소스 코드를 누구나 볼 수 있음 (유출 위험)   | **코드가 암호화/압축되어 있어 안전함**                        |
| **안정성**   | "내 컴퓨터에선 되는데 현장에선 안 돼요" 발생 빈번       | **내 컴퓨터 환경을 그대로 박제해서 가져가므로 100% 동일작동** |
| **편의성**   | Python 깔고, 라이브러리(`pip install`) 깔고 설정해야 함 | **그냥 `Setup.exe` 더블 클릭이면 끝 (Python 안 깔아도 됨)**   |
| **업데이트** | 파일 하나하나 덮어씌우다가 실수할 수 있음               | **새버전 `Setup.exe` 덮어쓰면 자동 업데이트 완료**            |

### 3.1. 2025 실무 보완 포인트

- 외부 또는 상용 배포용 설치 파일은 코드 서명하고, 모든 배포 파일은
  SHA-256을 함께 제공하여 위변조를 확인한다.
- Webview2 런타임 포함 또는 설치 체크.
- 업데이트 시 config.ini/로그/CSV는 ProgramData 또는 사용자 폴더에 분리 저장하여
  덮어쓰기 방지.
- 무인 설치 옵션(/S)과 롤백 패키지 준비.
- 현장 NAS 경로/드라이브 매핑 검증 후 설치 완료 처리.
- 설치/업데이트 시 기존 config.ini 및 사용자 데이터 백업/복원 절차를 기본
  제공한다.
- 언인스톨 시 사용자 데이터 보존 여부를 선택 가능하게 설계한다.
- config.ini 변경은 재시작 없이 적용되도록 hot reload 적용(일부 항목은 예외).
- config.ini 변경 감지(watcher) 기능 포함(외부 수정 자동 적용).
- 재시작 필요 항목은 UI에 pending으로 표시되도록 운영 기준을 명확히 한다.

### 3.2. 코드 서명 적용 기준

`2026-08-06` 현재 SmartFactoryLogger는 소유자 한 명이 통제된 환경에서 사용하는
개인용 프로그램이다. 이 범위에서는 유료 Authenticode 인증서 구매와 실제 서명
등록을 보류할 수 있다. 보류는 코드 서명이 완료됐다는 뜻이 아니며, 미서명 설치본은
다음 통제를 모두 만족해야 한다.

- 설치 전에 실행 대상 kit 밖의 신뢰된 Git commit 또는 별도 인증 채널에서 확보한
  SHA-256과 실제 파일 해시가 정확히 일치해야 한다. 같은 미서명 kit 안의 sidecar만
  신뢰 기준으로 사용하지 않는다.
- 설치본, 빌드 commit, 검증 도구가 묶인 commit-bound release kit를 사용해야 한다.
- 설치 대상과 운영자가 통제되는 개인·내부 환경 밖으로 파일을 전달하지 않는다.
- 자체 서명 인증서는 개발 시험에만 사용할 수 있으며 production 서명을 대체하지
  않는다.

다음 중 하나라도 해당하면 보류를 종료하고 공개 신뢰 Authenticode 서명을 적용한다.

- 고객, 협력사 또는 제3자에게 설치 파일을 전달한다.
- 불특정 사용자가 다운로드할 수 있도록 공개한다.
- 유료 판매, 상용 납품 또는 조직 차원의 배포를 시작한다.
- Windows 게시자 신뢰나 SmartScreen 경고 완화가 운영 요구사항이 된다.

향후 서명 방식을 선정할 때는 내보낼 수 있는 PFX를 전제로 하지 않는다. 인증기관의
정책에 따라 USB 보안 토큰, HSM 또는 클라우드 서명을 사용할 수 있으므로, 선택한
방식에 맞춰 GitHub Actions와 비밀정보 관리 방식을 별도로 설계한다. 개인키와 인증서
비밀번호는 저장소에 커밋하지 않는다.

## 4. 결론

**"걱정하지 마십시오. 오히려 더 편해집니다."**

V2 웹 기술로 전환하면 "빌드 과정"은 개발자 PC에서 한 번 수행해야 하지만, 막상
현장에 가서 배포하는 작업은 **"USB 꽂고 -> 설치 파일 더블 클릭"**으로 끝납니다.
이것이 2025년 상용 소프트웨어 배포의 **정석(Standard)**입니다.
