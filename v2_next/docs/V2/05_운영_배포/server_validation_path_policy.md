# 서버 검증 경로와 정리 기준

작성일: 2026-09-15. 상태: 앞으로 사용할 기준 확정 / 기존 서버 경로 미이관.

## 단일 부모 경로

사용자 요청에 따라 이후 새 서버 검증 도우미의 관리 루트는
`C:\ProgramData\SFLOps`로 고정한다. 별도 버전/GUID 최상위 루트를 늘리지 않는다.
이 문서를 추가했다고 서버에 폴더를 만들거나 기존 도우미의 경로가 바뀐 것은 아니다.

```text
C:\ProgramData\SFLOps\
  inbox\                    전송 파일 수신; 실행 전 외부 해시 검증
  releases\v1026\<id>\     버전별 검증된 설치본·Canary·원본 manifest
  runs\<id>\               실행별 raw_private·sanitized_share·결과
  audits\<id>\             기존 증거를 보존한 별도 사후감사
  backups\<id>\            backup·restore·검증 영수증
  tmp\<id>\                도구가 소유한 임시 파일
  inventory\<id>\          탐색·삭제 후보·보존 목록·정리 결과
```

권한은 자식 폴더별로 구분한다. releases/audits/backups/inventory 및 원본 증거는
관리자/SYSTEM 전용을 기본으로 한다. 표준 사용자 프로세스가 기록해야 하는 해당
run의 자식에만 필요한 SID/권한을 부여한다. 루트 전체에 Users 쓰기 권한을 주지 않는다.
inbox는 신뢰된 실행 경로가 아니며 검증 후 별도 보호된 자식으로 복사한다.
기존 Desktop 전송 경로는 이행 기간 읽기 원본으로만 취급하고, 새 검증 결과를 쌓지 않는다.

유일 식별자는 부모가 아닌 자식에서 사용한다. 동일 경로 재사용/덮어쓰기는 금지한다.
새 생성 경로는 정규화·부모 경계·reparse·기존 항목·권한을 검증한다.
가장 긴 최종 산출물 경로를 기존 PowerShell 5.1 예산(240자)에 맞춰 시험한다.
기존 canary의 긴 runtime_validation 하위 경로를 그대로 이식해 예산을 넘기지 않는다.

## 운영 폴더는 정리 대상이 아니다

이 단일 루트 정책은 검증/배포 준비 자료에 적용한다. 현재 프로그램의 설치 경로,
설정/수집 데이터, Electron 사용자 프로필을 임의로 이동하지 않는다.

- `C:\Users\user\AppData\Roaming\SmartFactoryLogger`
- `C:\Users\user\AppData\Roaming\smart-factory-logger-v2`
- `C:\Users\user\AppData\Local\Programs\smart-factory-logger-v2`

이들까지 한 루트로 바꾸려면 앱 경로 설정, 표준 사용자 ACL, 데이터 이관,
설치/업그레이드/롤백 계약을 별도 변경·검증해야 한다. 이번 정리에서 수행하지 않는다.

## 기존 경로를 일괄 이동하지 않는다

이미 전달한 helper/ZIP은 해시와 과거 절대경로에 결합돼 있다. 기존 파일의 경로 문자열을
치환하거나 결과 JSON을 새 주소로 수정하지 않는다. 기존 도우미는 LEGACY_PINNED로 보존하며
새 작업은 새 루트에 맞춘 별도 버전·해시·시험 결과를 갖춰 발행한다.

보존 자료 이관이 필요하면 복사→파일별 검증→원래 경로를 포함한 외부 이관 manifest→
의존 helper/작업 참조 재검토 순서로 한다. 기존 증거의 내용은 그대로 둔다.
원본 제거는 이관 완료와 삭제 대상 목록 확정 후 별도 단계로 수행한다.
미래 경로 정책만으로 현장 기존 도우미가 단일 루트를 따르게 됐다고 보고하지 않는다.

## 영구 삭제 조건

파일 나이, 이름에 tmp/old/HOLD가 있음, 폴더가 여러 개라는 이유만으로 삭제하지 않는다.

1. 정확한 서버 절대경로와 최종 하위 파일/폴더 목록을 확보한다. 링크는 따라가지 않는다.
2. 실행 중 제품·원본 데이터·백업·v1.0.25 증거/복구 설치본·v1.0.26 후보를 보존한다.
3. 반복 배포본은 실제 바이트/manifest 일치를 확인한다. 재실행 결과는 복제본과 다르다.
4. 예약 작업·서비스·바로가기·실행 helper·증거 참조 여부를 확인한다. 프로세스 이름만으로
   파일 미사용을 증명하지 않는다. 모르면 HOLD한다.
5. 최종 keep/delete 목록, 파일 수/크기, 해시, 복구 불가 범위를 사용자에게 제시한다.
6. 그 정확한 목록에 대한 승인을 받은 뒤에만 같은 PowerShell에서 LiteralPath로 삭제한다.
   삭제 직전에 경계·해시·사용 상태를 다시 확인한다. 전체 C:\tmp, ProgramData, Desktop,
   AppData나 `SFL*` 와일드카드 일괄 삭제는 금지한다.
7. 삭제 결과와 남은 보존 파일을 재검증하고 영구 삭제로 복구할 수 없는 범위를 보고한다.

### 2026-09-15 제한된 중복 삭제 승인

사용자의 “정리 승인 필요없는건 과감히 삭제”는 이미 조사한 자료 중 불필요한 자료의
정리를 실행하라는 승인으로 기록한다. 이 승인에 따라 새 1차 도우미는 고정된
`pre_v1020_quarantine_20260813_092302` 안에서 직계 보존 ZIP에 모든 파일의
상대경로·길이·SHA256이 일치하는 압축 해제 폴더만 실행 시 확정해 삭제할 수 있다.
정확한 동적 목록을 콘솔과 durable PLAN에 먼저 기록하며 추가 승인 입력은 요구하지 않는다.
이 경우 승인된 범위는 해당 동일 바이트 중복 제거 규칙이며, 유일한 증거·설정/백업이나
다른 서버 경로까지 포괄 승인된 것으로 간주하지 않는다. 불확실하면 보존하거나 중단한다.
직계 ZIP/단독 파일·관련 백업·R4 연결 자료·현재 v1.0.25/v1.0.26 자료는 유지한다.

## 이번 1차 탐색 범위

`scripts/server-path-audit/read-server-paths.ps1`는 고정된 서버 경로와 관련 이름의
직계 자식만 탐색한다. 숨김 항목 포함, reparse 미추적, 개별 오류/제한을 기록한다.
파일 내용·ZIP·API는 읽지 않고, 삭제/복사/이동/앱 실행 없이 콘솔 JSON만 출력한다.
이 명령을 개발 PC에서 실행해 얻은 결과를 서버 조사 결과로 사용하지 않는다.

90초 단계 예산·디렉터리당 5,000항목·검색당 100후보·총 150루트 제한이 있다.
실시간 데이터 전체를 재귀 열거하거나 대형 파일을 해시하지 않는다.
따라서 출력 크기는 전체 하위 용량이나 회수 가능한 공간이 아니고,
발견되지 않았다는 결과도 서버 전체의 부재 증명이 아니다.
사용자 지정 설정/env 경로, 다른 드라이브·사용자, NAS, 작업/서비스 참조는 후속 조사다.
이 단계에는 영구 삭제 실행 코드가 없다.
