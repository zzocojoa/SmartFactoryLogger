# 서버 검증 경로와 정리 기준

작성일: 2026-09-15. 개정일: 2026-09-20. 아래 새 기준이 과거 SFLOps 고정 기준을 대체한다.

## 접근 가능한 작업 경로

사용자의 “앞으로 서버 컴퓨터, 개발 컴퓨터에서 접근이 불가능한 SFLOps에서 진행하지 마라”는
지시에 따라 양쪽 PC에서 `SFLOps`를 새 작업·검증·빌드·전송·결과 저장 경로로 사용하지 않는다.
기존 자료는 과거 증거로 보존한다. 참조가 꼭 필요하면 원본을 읽고 접근 가능한 새 작업 폴더에
검증된 사본과 출처를 기록한다. 기존 자료의 이동·삭제·권한 변경을 이 지시에서 추론하지 않는다.

기본 위치는 Windows가 알려 주는 실제 사용자 바탕화면의 `SmartFactory` 아래다.
현재 사용자 경로의 예는 `C:\Users\user\Desktop\SmartFactory`이며 실행별 새 폴더를 사용한다.
개발 PC와 서버 각각 일반 탐색기에서 접근 가능함을 확인한다. 다른 경로를 사용자가 지정하면
그 경로를 따른다. 운영 설치/AppData 경로는 검증 작업 폴더와 별개로 유지한다.

```text
C:\Users\user\Desktop\SmartFactory\
  <새 검증 묶음>\           실행 파일·설명서·해시·기준 자료를 함께 보관
    results-<시각>-<GUID>\   새 결과와 해시; 운영 사용자가 읽고 복사 가능
  <새 개발 검증 기록>\      개발 PC의 시험·전송·회수 영수증
```

부모 폴더의 소유권이나 ACL을 바꾸는 것을 검증 선행 조건으로 요구하지 않는다.
필요한 보호 권한은 도우미가 새로 만드는 결과 자식에만 적용하며 관리자/SYSTEM 쓰기와
운영 사용자의 읽기·탐색·복사를 함께 보장한다. 모든 사용자가 쓰도록 권한을 넓히지 않는다.
실행 도우미는 외부 고정 SHA-256으로 확인한 같은 잠금 바이트를 실행하고 기준 자료도 고정
해시로 확인한다. 결과 해시는 콘솔에 출력하여 회수 파일과 대조한다. 사용자 쓰기가 가능한
부모 아래 보호된 결과 폴더는 적대적 경로 교체에 대한 완전한 방어를 뜻하지 않는다.

유일 식별자는 부모가 아닌 자식에서 사용한다. 동일 경로 재사용/덮어쓰기는 금지한다.
새 생성 경로는 정규화·부모 경계·reparse·기존 항목·권한을 검증한다.
가장 긴 최종 산출물 경로를 기존 PowerShell 5.1 예산(240자)에 맞춰 시험한다.
기존 canary의 긴 runtime_validation 하위 경로를 그대로 이식해 예산을 넘기지 않는다.

## 서버 최종 복사까지 Codex가 담당

2026-09-20 사용자 지시: 이후 서버 검증에 필요한 자료는 Codex가 서버 컴퓨터의
최종 작업 폴더까지 복사한다. 개발 PC에서 파일을 만들거나 공유 드라이브에 올린
상태로 사용자에게 전송을 넘기지 않는다.

`SFLOps`나 과거 도우미의 보호된 `runs`를 새로 만들거나 복구하지 않는다.
2026-09-20 과거 도우미의 `ops-owner` 중단은 설치본 불일치나 검증 통과가 아니다.
필요한 기준 자료가 동봉되어 있는지, 새 결과 경로를 정상 생성하고 사용자가 읽을 수 있는지를
새 도우미의 사전 시험으로 확인한다. 폴더 존재만으로 실행 준비 완료라고 보고하지 않는다.

1. 개발 PC에서 검증 도우미·설명서·해시를 준비하고 검증한다.
2. 개발 PC의 `Z:\SmartFactory\YYYYMMDD\send` 아래 실행별 새 전송 폴더로 복사하고 원본과 해시를 비교한다.
3. 사용자가 지정한 Chrome 원격 데스크톱을 브라우저/컴퓨터 도구로 조작한다.
   서버의 `Z:\`에서 자료를 확인하고 서버 바탕화면 `SmartFactory\<새 검증 묶음>`으로
   복사한다. 필요한 압축 해제까지 담당하며 기존 폴더나 파일을 덮어쓰지 않는다.
4. 서버 화면에서 최종 절대경로와 필요한 파일의 존재를 확인한 뒤 그 경로를 사용해
   다음 실행 단계를 안내한다. 전송 영수증에는 공유 위치, 서버 로컬 위치, 파일 목록,
   해시 확인 범위를 구분해 기록한다. 화면 확인을 서버 로컬 해시 검증으로 보고하지 않는다.
5. 실행 후 결과를 `Z:\SmartFactory\YYYYMMDD\return` 아래 실행별 새 폴더로 회수하고
   개발 PC에서 분석하는 작업도 Codex가 담당한다.
   원본 증거를 보존하고 민감한 결과는 기존 공유 권한과 사용자 지정 전달 범위를 지킨다.

공유 드라이브 `Z:\`는 전달용이며 서버의 최종 작업 위치를 대신하지 않는다.
로컬 수신만으로 실행 신뢰가 성립하지 않으며 위 해시·새 결과 폴더 보호 기준을 계속 적용한다.
직접 실행을 제한하는 도구 규칙이나 관리자 인증이 있으면 가능한 복사·압축 해제·파일 확인을
먼저 끝낸다. 사용자에게 필요한 실행 단계와 정확한 제한 근거만 안내하며, 실행을 위해
보안 규칙이나 해시 검증을 우회하지 않는다. 원격 연결/권한 문제로 최종 복사를 못 한 경우
실제 완료 위치와 남은 작업을 명시하고 서버 전달 완료라고 보고하지 않는다.

## 공유 드라이브 공통 부모 폴더

2026-09-20 사용자가 Z 드라이브에 흩어진 폴더를 부모 폴더 아래에서 관리하도록 지시했다.
이후 새 작업은 다음 구조를 사용하며 `Z:\` 루트에 실행별 폴더를 추가하지 않는다.

```text
Z:\SmartFactory\
  YYYYMMDD\
    send\<묶음 이름>\       개발 PC에서 서버로 전달
    return\<회수 이름>\     서버 최종 사본·결과 회수
    records\                전송 기록·이전/새 경로 대응표
```

현재 지시에 따라 이번 작업이 생성한 기존 공유 폴더 14개만 `20260920` 아래로 이동했다.
동일 공유 드라이브 내 디렉터리 이동으로 처리하고 상대 파일/폴더 목록, 파일 크기·수정 시각,
최상위 폴더 ACL을 전후 대조했다. 현재 준비 묶음 5파일은 추가로 SHA256을 재대조했다.
전체 과거 자료를 새로 전수 해시 검증했다고 보고하지 않는다.

이전/새 경로 대응표는 `Z:\SmartFactory\20260920\records\path-map.json`이며,
개발 기록은 `Desktop\SmartFactory\Z_ORGANIZATION_20260920_R1`에 보존한다.
기존 영수증·도우미의 내용과 해시는 바꾸지 않는다. 과거 기록의 Z 절대경로는 당시 위치이며
현재 위치는 대응표로 찾는다. 구도우미를 재사용할 때는 기존 고정 경로 계약을 다시 확인한다.
현재 `SFL_TRC_PREP_R2`는 서버 로컬 경로만 사용하므로 이번 공유 경로 변경의 영향을 받지 않는다.
다른 공유 자료, 원본 CSV, 서버 로컬 실행 폴더, 운영 AppData/설치 폴더는 이번 정리 대상이 아니다.
이 명시적 공유 폴더 정리 지시는 아래의 기존 해시 결합 자료 자동 이관 금지와 구분한다.

## 운영 폴더는 정리 대상이 아니다

이 작업 경로 정책은 검증/배포 준비 자료에 적용한다. 현재 프로그램의 설치 경로,
설정/수집 데이터, Electron 사용자 프로필을 임의로 이동하지 않는다.

- `C:\Users\user\AppData\Roaming\SmartFactoryLogger`
- `C:\Users\user\AppData\Roaming\smart-factory-logger-v2`
- `C:\Users\user\AppData\Local\Programs\smart-factory-logger-v2`

이들까지 한 루트로 바꾸려면 앱 경로 설정, 표준 사용자 ACL, 데이터 이관,
설치/업그레이드/롤백 계약을 별도 변경·검증해야 한다. 이번 정리에서 수행하지 않는다.

## 기존 경로를 일괄 이동하지 않는다

이미 전달한 helper/ZIP은 해시와 과거 절대경로에 결합돼 있다. 기존 파일의 경로 문자열을
치환하거나 결과 JSON을 새 주소로 수정하지 않는다. 기존 도우미는 LEGACY_PINNED로 보존하며
새 작업은 새 루트에 맞춘 별도 버전·해시·시험 결과를 갖춰 발행한다.

보존 자료 이관이 필요하면 복사→파일별 검증→원래 경로를 포함한 외부 이관 manifest→
의존 helper/작업 참조 재검토 순서로 한다. 기존 증거의 내용은 그대로 둔다.
원본 제거는 이관 완료와 삭제 대상 목록 확정 후 별도 단계로 수행한다.
미래 경로 정책만으로 현장 기존 도우미가 단일 루트를 따르게 됐다고 보고하지 않는다.

## 영구 삭제 조건

파일 나이, 이름에 tmp/old/HOLD가 있음, 폴더가 여러 개라는 이유만으로 삭제하지 않는다.

1. 정확한 서버 절대경로와 최종 하위 파일/폴더 목록을 확보한다. 링크는 따라가지 않는다.
2. 실행 중 제품·원본 데이터·백업·v1.0.25 증거/복구 설치본·v1.0.26 후보를 보존한다.
3. 반복 배포본은 실제 바이트/manifest 일치를 확인한다. 재실행 결과는 복제본과 다르다.
4. 예약 작업·서비스·바로가기·실행 helper·증거 참조 여부를 확인한다. 프로세스 이름만으로
   파일 미사용을 증명하지 않는다. 모르면 HOLD한다.
5. 최종 keep/delete 목록, 파일 수/크기, 해시, 복구 불가 범위를 사용자에게 제시한다.
6. 그 정확한 목록에 대한 승인을 받은 뒤에만 같은 PowerShell에서 LiteralPath로 삭제한다.
   삭제 직전에 경계·해시·사용 상태를 다시 확인한다. 전체 C:\tmp, ProgramData, Desktop,
   AppData나 `SFL*` 와일드카드 일괄 삭제는 금지한다.
7. 삭제 결과와 남은 보존 파일을 재검증하고 영구 삭제로 복구할 수 없는 범위를 보고한다.

### 2026-09-15 제한된 중복 삭제 승인

사용자의 “정리 승인 필요없는건 과감히 삭제”는 이미 조사한 자료 중 불필요한 자료의
정리를 실행하라는 승인으로 기록한다. 이 승인에 따라 새 1차 도우미는 고정된
`pre_v1020_quarantine_20260813_092302` 안에서 직계 보존 ZIP에 모든 파일의
상대경로·길이·SHA256이 일치하는 압축 해제 폴더만 실행 시 확정해 삭제할 수 있다.
정확한 동적 목록을 콘솔과 durable PLAN에 먼저 기록하며 추가 승인 입력은 요구하지 않는다.
이 경우 승인된 범위는 해당 동일 바이트 중복 제거 규칙이며, 유일한 증거·설정/백업이나
다른 서버 경로까지 포괄 승인된 것으로 간주하지 않는다. 불확실하면 보존하거나 중단한다.
직계 ZIP/단독 파일·관련 백업·R4 연결 자료·현재 v1.0.25/v1.0.26 자료는 유지한다.

## 과거 1차 탐색 범위: 보존 기록

`scripts/server-path-audit/read-server-paths.ps1`는 고정된 서버 경로와 관련 이름의
직계 자식만 탐색한다. 숨김 항목 포함, reparse 미추적, 개별 오류/제한을 기록한다.
파일 내용·ZIP·API는 읽지 않고, 삭제/복사/이동/앱 실행 없이 콘솔 JSON만 출력한다.
이 명령을 개발 PC에서 실행해 얻은 결과를 서버 조사 결과로 사용하지 않는다.

90초 단계 예산·디렉터리당 5,000항목·검색당 100후보·총 150루트 제한이 있다.
실시간 데이터 전체를 재귀 열거하거나 대형 파일을 해시하지 않는다.
따라서 출력 크기는 전체 하위 용량이나 회수 가능한 공간이 아니고,
발견되지 않았다는 결과도 서버 전체의 부재 증명이 아니다.
사용자 지정 설정/env 경로, 다른 드라이브·사용자, NAS, 작업/서비스 참조는 후속 조사다.
이 단계에는 영구 삭제 실행 코드가 없다.
