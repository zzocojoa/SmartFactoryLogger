# v1.0.26 운영 도구 머지 검토

검토일: 2026-09-19

## 판정

소스 변경의 리뷰 차단 항목은 수정·회귀시험·읽기 전용 재리뷰로 해소했다.
선별한 운영 도구/문서만 커밋하고 PR의 GitHub CI가 통과하는 조건으로
머지 가능하다. 실제 커밋·push·PR 생성·merge·서버 실행은 하지 않았다.
미추적 파일을 포함한 전체 작업 폴더를 일괄 추가하는 판정이 아니다.

## 브랜치 목적과 범위

브랜치: codex/v1026-server-stage-preflight

검토 시 HEAD와 origin/master는 c03f7c76ff6e75bfe330275ac0fa01326f357261,
ahead/behind는 0/0이었다. 변경은 커밋되지 않은 작업 파일에 있었다.

출발점은 v1.0.26 전송본의 정적 staging/preflight였다. 현재 작업은 그 후의
최소 백업/설치/설치본 검증, 서버 경로·ACL 점검, 개발 PC의 검증 파일 관리와
정리 도구까지 포함한다. 제품 backend/frontend 성능 수정 브랜치가 아니다.
관련 UI 성능 변경 e3d094b(PR #189)는 이미 기준 브랜치 이력에 있다.

머지 후보는 scripts 소스·합성 fixture·문서, 서버 경로 정책, README/AGENTS,
.gitignore와 오프라인 CI이다. 개인 관리본, .tmp, artifacts, 실제 프로필/쿠키,
별도 branding 이미지, 여섯 현장/정리 보고서는 이 후보에서 제외했다.
제외 파일은 삭제하지 않았다.

## 해결한 문제

| 문제 | 조치 |
| --- | --- |
| 관리기 일부 명령이 미완료 ACL/정리 상태를 건너뜀 | 공통 읽기 검사와 저장 직전 검사를 적용; 명령 진입점/저장 차단 회귀시험 |
| 설치 승인 대기 중 앱이 재시작할 수 있음 | r2에서 승인 직후 및 실제 COM 실행 직전 중지 재확인; 조회 실패도 HOLD |
| 백업 영수증만 확인하고 실제 데이터는 재확인하지 않음 | r2에서 backup/restore 및 현재 원본의 내용·목록·메타데이터와 state-map을 재검증 |
| dist 시험이 Git에서 제외된 개인 관리본에 의존 | 고정 계약을 메모리 합성 fixture로 시험 |
| 새 r2 builder의 검증/복사 바이트 결합 공백 | 영수증 읽기 핀, 복사본·ZIP fact의 검증 해시 비교, ZIP 재개방 검사 |

새 체크아웃에서 드러난 시험 경로의 AppData 오인, PS5.1 모듈 검색 경로와
긴 fixture 경로 문제도 시험/runner 범위에서 교정했다. 운영 경로 허용 규칙을
완화하지 않았다.

기존 해시 결합 r1 helper/엔진은 변경하지 않았다. r1은 역사적 증거 대조용이며
신규 실행에는 사용하지 않는다. r2는 일반 업그레이더가 아니고 과거의 정확한
백업/stage에 결합된다. 현재 운영 서버 재설치 승인이 아니다.

## 검증 결과

개인 관리본 및 기존 산출물이 없는 별도 Git tree 체크아웃에서
scripts/run-ops-offline-tests.cjs의 실행 26개가 모두 성공했다.

- Node: 18개 시험 파일, 183 tests, 실패 0.
- PowerShell fixture: 23개 시험 실행 성공.
- 구문 분석: PowerShell 7에서 107개, PS5.1 대상 56개 성공
  (서로 겹치는 소스를 별도 런타임에서 검사; 고유 시험 수로 합산하지 않음).
- r2 실제 AssertBackup 경로 및 builder gate 합성 검증 34개 통과.
- 로컬 최종 r2 패키징 성공, ZIP 전 항목 재개방/해시 확인 성공.
- 잘못된 외부 영수증 해시로 패키징하면 출력 폴더 생성 전에 거부됨.
- 원본 r1 SHA256: 7943B476C75BF5FC1B8F1CB9D83C6018E787F4ACCEA17D42BF0C6C670FF42C53.
- 엔진 소스 SHA256: D2F56CE62ADA4155F68CC947A81669A1AE3A1DB200076F9DA6AE165E302A8E7D.
- 개인 관리본 해시는 검토 전후 동일했다. 실제 Git index와 branch ref는 변경하지 않았다.

시험한 소스 tree: ce204fdd2d6bf091bc58a0acecaeab1d69b8f71f.
이후 변경은 본 보고서와 CI의 루트 .gitattributes 경로 trigger 추가뿐이다.
임시 index/tree는 검증용이며 commit이나 별도 worktree 등록이 아니다.

두 역사적 파일의 기존 EOF 빈 줄은 바이트 보존 때문에 그대로 남겼다.
blank-at-eof를 제외한 Git whitespace 검사는 통과했다.

## 남은 검증 한계

- GitHub hosted CI는 아직 실행하지 않았다. 로컬에서 동일 runner만 실행했다.
- 실제 서버 자료가 필요한 시험 8개는 명시적으로 제외했다. 제외는 통과가 아니다.
- repair-dependency-acl은 -PureOnly 15개만 실행했다. 비관리자 전체시험의
  SeSecurityPrivilege 실패를 통과로 처리하지 않았다. 실패한 합성 fixture는 보존했다.
- dist의 관리자 ACL/copy 검사는 이번 비관리자 실행에서 수행하지 않았다.
- 서버 설치, COM 사용자 토큰, 실제 원본 백업/복원, 장시간 성능/Canary와 제품 전체
  빌드/회귀시험은 이번 운영 도구 검토 범위가 아니다.
- r2의 중지/원본 검증은 시점별 확인이며 동시 작업자에 대한 원자적 잠금이 아니다.

## 운영 위험과 복구

위험도는 높음: 수동 실행 가능한 설치·삭제·ACL 도구를 보관하는 변경이다.
제품 런타임 코드와 실제 데이터/ACL에는 이번 변경을 적용하지 않았다.

신규 helper는 검증 불일치에서 HOLD하고 자동 재시도/설치/정리/롤백을 하지 않는다.
검사 근거·해시·실행별 요약을 남기며, 실제 관리 목록과 운영 파일을 재작성하지 않는다.
코드 통합의 복구는 해당 커밋 revert이다. 이미 수행한 파일 삭제나 서버 설치를
Git revert가 되돌려 주지는 않는다. 운영 복구는 보존 백업·영수증을 별도 검토해야 한다.

다음 조치는 이 선별 범위의 커밋/PR 생성 및 GitHub CI 통과 확인이다.
이 보고서는 서버 작업이나 추가 삭제를 승인하는 실행 계획이 아니다.
