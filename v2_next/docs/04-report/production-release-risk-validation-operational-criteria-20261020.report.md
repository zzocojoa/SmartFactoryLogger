# 운영 성능 판정과 실제 이미지 화면 관찰 방식 개정

최신 완료 범위는 아래 **「120분 관찰과 해당 실행의 닫힌 저장 데이터 검산 완료」**에 기록했다.
revision4의 실제 화면 계측은 COMPLETE, 요청·load 항목은 PASS이며,
정상 종료 검산 후 진단 연결을 제거하고 일반 실행으로 복귀했다.
이전 revision3의 종료 경계 INCOMPLETE는 당시 원시 자료와 함께 보존한다.
앞선 두 종료 실행의 저장 이미지8,822개 검사는 통과했다. 후속120분 수집·세대결합과
해당 전체 실행의 CSV41,487행·이미지8,912개 검산도 완료했다. 운영 적합성·물리 화면 연속성·
전체 과거 데이터 QA의 완료 판정은 아직 하지 않는다. 2026-10-21 사용자 확인의 약3대·각1화면
동시 조회 요구는 계획/설계에 추가했으며, 기존 단일 화면 결과가 이 조건의 통과를 뜻하지 않는다.
초기 구현 결과와 과거 해시 결합 평가 파일은 당시 기록으로 유지한다.

2026-10-22 VM의 1탭·3탭·독립3클라이언트 비교 자료 검토는 완료했다. 실제3대 PC의
네트워크·화면 검증은 아니다. 원시 web-vitals 재검토에서 초기 CLS0.5603–0.5932가
7페이지 중6페이지에 기록되어 기존0.25 비교값을 넘었다. 인과 원인은 미확정이며 초기 자동
스크롤과 실제 layout-shift 항목/요소 좌표가 없어 UI 수정 근거로 단정하지 않는다.
누적 최대값 변화가 없다고 이후 작은 화면 이동까지0이라고 판단하지 않는다.
최신 전체 상태와 조사 우선순위는 [목표 정합성 점검](production-release-risk-validation-goal-alignment-20261022.report.md)을 따른다.

2026-10-20 사용자 승인에 따라 검증 도구와 판정 문서를 수정했다.
초기 변경 범위는 개발 PC의 소스·격리 검사·보존 자료 재검토였으며, 이후 현장 관찰은
각 후속 절에 별도로 기록한다. 장비 설정, 제품의 수집/저장/화면 갱신 주기,
설치본, 운영 승격은 이번 관찰에서도 변경하지 않았다.

## 판단 규칙

| 항목 | 이후 운영 관찰 | 남겨야 하는 근거 |
|---|---|---|

| 표본 누락·취소·잘못된 기록 | 계측 INCOMPLETE | 누락/취소/미계측/유효하지 않은 시계와 슬롯 |
| 실제 이미지 화면 | 기존 화면의 요청·load/error·가시성·포커스를 관찰 | 실제 load 간격, 시작/끝 미관찰 구간, 오류 이벤트 |
| 고정 250ms 이미지 요청 | 별도 부하/과거 재현용 `observe` | 당시 원시 값과 기존 FAIL 유지 |

| 운영 적합성 | 요구 시간·실제 화면·저장 증거가 없으면 NOT_EVALUATED | 공정 요구와 각 검증의 독립 결과 |

예를 들어 성공한 health 425ms는 `request_status=PASS`, 초과 통계 1건,
`operational_performance=NOT_EVALUATED`다. timeout은 요청 FAIL이다.
이미지 측정 139회 누락은 저장 이미지 139개 손실이나 화면 정지 횟수로 변환하지 않는다.
연속 초과 표본 사이 시간도 그동안 장애가 지속됐다는 증거가 아니다.
기록 공백을 건너뛰어 연속 초과나 성공 응답 간격을 계산하지 않는다.

## 구현과 사용 경계

- `field_operational_assessment.py`: 계측 완전성, 요청 결과, 지연 통계, 운영 적합성을 분리한다.
  기존 `summarize_channel`을 보존해 당시 계약의 결과도 재현한다.
- `field_runner.py`의 새 명시적 모드 `operational-observe`:
  기존 요청 schema·설치/설정 해시·앱 실행 세대·15분/120분 시간 제한을 유지한다.
  HTTP 관찰은 health 2초/data 6초이며 추가 이미지 요청을 만들지 않는다.
  초기·최종 health와 인증 control-health는 지연만으로 결합 검사를 실패시키지 않는다.
  응답 오류·본문/세대/설정 불일치는 계속 실패한다.
- 관찰 결과의 `status_scope=COLLECTION_AND_BINDING_ONLY`를 상위 결과에도 남긴다.
  수집/결합 PASS나 exit0을 운영 성능 PASS로 해석하지 않는다.
  실행 완료 조건을 못 채워 상위 상태/exit가 실패하더라도
  `observation_status=INCOMPLETE`, `incomplete_evidence`와 요청 오류를 구분해 읽는다.
  manifest/hash 불일치는 증거 무결성 실패이며 단순 측정 공백으로 완화하지 않는다.
- `observe_operator_image.cjs`: 이미 열린 정확한 페이지에 연결하는 수동 개입 없는 관찰기다.
  화면의 기존 로드 완료 → 설정된 대기 → 다음 요청 동작을 관찰한다.
  이미지 재요청·타이머 교체·페이지 이동·가시성/포커스 강제 변경을 하지 않는다.
  대상은 같은 origin의 이미지 endpoint와 `.camera-image` load/error다.
  관찰 시간과 기록 수를 제한하며 종료/연결 중단 후 자체 리스너·타이머를 정리한다.
  연결 해제 시 기존 브라우저/페이지는 유지한다.

구 `observe`와 기존 timing/trace 도우미의 기본 동작은 과거 재현·부하 분석을 위해 유지했다.
새 도구를 이전 해시 결합 묶음에 덮어쓰면 안 된다. 기존 서버 exe는 이번 변경을 포함하지 않는다.
현장 실행 전에 새 검증 묶음의 빌드·출처·파일별 해시와 현재 앱 세대를 다시 결합해야 한다.
제품 설치본을 다시 만들거나 설치해야 한다는 뜻은 아니다.

개발 소스의 지원 모드 확인:

```powershell
C:\Python312\python.exe scripts/field-v1028/field_runner.py --describe
```

새 요청은 기존 `sfl-field-run-request-v1`의 승인된 필드를 사용하되
`mode`를 `operational-observe`로 명시한다. 기존 요청 파일을 고쳐 재사용하지 않고
새 요청·SHA256·실행 폴더를 준비한다. CLI는 이 모드를 권장 관찰 경로로 안내한다.

이미 연결 가능한 **기존 loopback CDP endpoint와 정확한 페이지 URL을 확인한 경우**의 템플릿:

```powershell
node scripts/field-v1028/observe_operator_image.cjs `
  --cdp "<확인한 http://127.0.0.1:포트>" `
  --page-url "<이미 열린 정확한 대시보드 URL>" `
  --run-id "<해당 관찰 실행 ID>" `
  --duration-ms 900000 `
  --out "<새 실행 폴더의 절대경로>\operator-image.json"
```

출력 폴더는 미리 존재하고 결과 파일은 새 이름이어야 한다. 서버의 remote debugging은
이번에 켜지 않았다. CDP 접속 경로나 앱 세대와의 연결을 검증하지 못하면 현장 화면 검증은
미완료다. Chrome에서 얻은 결과를 Electron 작업자 창의 결과로 바꿔 적지 않는다.
DOM load는 실제 모니터 표시나 센서 프레임 생성 시각을 증명하지 않는다.
가려짐/포커스 이탈·미종료 요청·기록 상한·관찰기 소실·load 부족은 INCOMPLETE다.

## 설계 대조와 남은 현장 조건

이번 승인 범위의 설계 5항목(판정 분리, 명시적 새 경로, 오류/누락 구별,
실제 UI 관찰 도구, 데이터 검증 유지)은 구현/회귀 대조 5/5다.
전체 R1–R6 달성률이나 현장 QA 통과율로 사용하지 않는다.

다음 입력이 확정될 때까지 운영 성능은 NOT_EVALUATED이고 정식 출시 HOLD다.
새로운 수치·실패율을 임의로 넣지 않았다.

| 필요한 운영 요구 | 기입 내용 | 현재 상태 |
|---|---|---|
| 작업자에게 필요한 화면 갱신 시간 | 정상/최대 허용 지연과 업무 영향 | 미확정 |
| 보존해야 할 최소 변화 시간 | 놓치면 안 되는 온도/설비 변화의 최소 지속 시간 | 미확정 |
| 예외 지연의 허용 범위 | 허용 지속 시간·빈도·관찰 기간·판정 책임자 | 미확정 |
| 실제 표시·저장 대응 | 같은 앱 실행의 UI·수신 fact·CSV·이미지·종료 잔량 연결 | 새 방식 현장 검증 미실시 |

SPOTViewer의 Modbus 순환 버퍼를 현재 HTTP 수집의 무손실 보장으로 사용하지 않는다.
관찰된 SPOT+ AL/40.38/100ms 프로파일은 별도 현장 기록이며 이번 현재값 확인이나
물리 성능 시험을 대신하지 않는다. 전체 데이터 QA·물리 시험·나머지 출시 조건은 유지한다.

## 추가 재검토: 증거 공백과 시계 검증

같은 날 사용자가 재검토와 추가 개선을 요청했다. 원본 timing-conditions 보고서,
현재 화면의 `scheduleNormalImageRefresh`/`handleImageLoad`, 현장 프로파일,
HTTP/자원/이미지 관찰기와 fact·CSV·이미지·종료 검사 코드를 다시 대조했다.
앞선 설계 5/5 대응은 요구별 구현 존재의 확인이며 모든 경계 조건의 무결함을 뜻하지 않는다.
다음 누락을 보완했다.
