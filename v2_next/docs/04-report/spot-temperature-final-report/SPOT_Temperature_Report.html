SPOT Temperature 결측·stale·반복값 처리 최종 수정 방향 보고서

대상: 2026-06-24 신규 통합 로그 3개 · AMETEK LAND SPOT/SPOT AL/Actuator 공식 문서 · 작성 2026-06-24 22:37 KST

최종 기술 요약

수정 방향은 “결측 처리 개선”이 아니라, 센서 출력 상태와 공정 컨텍스트를 서로 독립된 축으로 분리하는 것이다. 현재 관측된 6553.4 16,428행은 모두 AMETEK의 under-range 최종 출력으로 처리해야 하며, 이를 곧바로 통신 결측·no target·센서 고장으로 해석하면 안 된다. SPOT+의 temperature 값은 Time Function과 장비 모드 계산이 적용된 출력이고, under/over-range는 각각 6553.4/6553.5로 전송된다. [S3 p.2-1]

공정 컨텍스트를 적용하면 16,428행 중 14,429행(87.83%)은 Count 0~2 셋팅 구간, 1,999행(12.17%)은 이전 작업의 최종 Count가 유지된 금형 교체 직전 대기 구간으로 분류된다. 그러나 물리적 직접 원인은 Peak Picker Reset, 측정 대상의 시야 이탈, 저신호/가림, 실제 측정 범위 미만 중 어느 것인지 아직 확정할 수 없다.

6553.4는 “결측”이 아니라 공정 맥락이 필요한 under-range 출력이다

기존 Temperature_quality='missing'·source_missing 매핑은 수정해야 한다. 신규 로그에서 6553.4 행은 전부 HTTP 200, poll success, fresh 상태였고 장비 상태는 temperature_under_range였다. 따라서 원천이 없었던 것이 아니라 장비가 정상 응답으로 under-range 코드를 제공한 것이다.

금형 교체 전후로 6553.4가 두 구간에 집중된다

Count가 0으로 초기화되기 전에도 이전 작업의 마지막 Count가 유지된 정지 구간이 존재한다. Count 12·15·16·35·49에서의 1,999행은 모두 Speed=0, MainPress=0, BilletLength=0, extruder_process_state_online='stopped', cycle_state='idle'이었다. 이후 Count 0과 품번·금형 변경으로 이어졌으므로 생산 중 이상이 아니라 pre_changeover_hold로 확정 가능한 과거 구간이다.

물리 원인은 별도 미검증이다. SPOT AL의 Peak Picker가 Off Mode=Reset이면, Off Delay 종료 후 입력이 threshold를 다시 넘을 때까지 출력 신호를 의도적으로 under-range로 내릴 수 있다. 따라서 6553.4 = target 없음으로 고정 매핑해서는 안 된다. [S4 p.4-14]

또한 AMETEK Actuator는 금형 교체 후 profile 정렬과 hotspot autoscan을 지원하며, 좁은 단면에서 신호를 최대화하기 위한 재정렬이 필요할 수 있다. 이 문서 근거는 금형 교체 시점의 6553.4가 정렬 과정과 연관될 가능성을 높이지만, 현재 로그에는 Actuator 위치·scan 상태가 없어 확정 증거는 아니다. [S5 p.2]

수정 로직은 상태 머신과 사후 확정을 함께 사용해야 한다

pre_changeover_hold는 미래의 Count 0 또는 품번·금형 변경을 확인해야 확정되는 상태다. 따라서 realtime 행에서 즉시 확정값으로 기록하면 미래 정보를 사용하게 된다. 온라인에서는 후보 상태를 기록하고, 후속 이벤트가 발생하면 event fact 또는 정제 계층에서 이전 후보 구간을 확정해야 한다.

운영 차단 조건: 6553.4를 no_target 또는 센서 고장으로 확정 저장하지 않는다. temperature_under_range_cause는 진단값이 확보될 때까지 unknown 또는 *_candidate만 허용한다.

행 시점 freshness 보완이 필요하다. 현재 freshness는 snapshot capture 시점 기준으로 반복 저장된다. 로그 행 시점에서 timestamp_utc - spot_last_poll_completed_at을 재계산하면 3초를 넘는 행이 3건 있었다. 빈도는 작지만 운영 규칙은 spot_effective_age_ms_at_row를 기준으로 판단해야 한다.

v2.4는 네 단계로 배포한다

  1. P0 — shadow 스키마 패치: 세 축 필드, provisional/confirmed phase, 행 시점 age, unavailable reason, changeover_event_id를 추가한다. 기존 Temperature 운영값은 즉시 변경하지 않는다.
  2. P1 — observation/config fact 추가: alarmstatus, signalpc, d1temperature, d2temperature, e1out, e2out, SPOT 모드/App/range, Peak Picker 설정, Actuator position/scan을 수집한다. REST API는 Application instrument에서 이 값들을 함께 제공할 수 있다. [S3 pp.2-1~3-3]
  3. P2 — 통제시험: 6553.5 응답 주입, 5초/20초 통신 차단, malformed 응답, SPOT 서비스 재시작, logger 재시작, 실제 금형 교체 1건을 수행한다.
  4. P3 — 운영 승격: 아래 완료 기준을 모두 만족한 뒤 v2.4 운영 필드가 기존 Temperature_quality를 대체하도록 한다.

운영 승격 완료 기준

  • 6553.4/6553.5가 숫자 온도로 유입되는 사례 0건
  • under/over-range가 invalid로 저장되고 source_missing 오분류 0건
  • 행 시점 age 3초 초과 시 stale 판정 누락 0건
  • 이전 정상 온도 캐시를 현재값으로 사용하는 사례 0건
  • 실제 금형 교체에서 후보 구간이 Count 0/메타 변경 후 정확히 confirmed되는 비율 100%
  • realtime CSV의 모든 SPOT 참조가 spot_observation_fact에 매칭
  • SPOT/logger 재시작 시 service instance와 sequence 경계가 명확히 분리
  • 물리 원인이 확인되지 않은 6553.4는 원인 unknown 유지

운영 적용 전 확인할 현장 설정

  • 현재 설치 장비의 정확한 모델·firmware·SPOT 모드(App1 AL E 여부)와 측정 range
  • Peak Picker 사용 여부, Peaks/Valleys, threshold, On/Off Delay, Off Mode가 Reset인지 여부
  • Actuator 사용 여부와 금형 교체 시 autoscan trigger 방식, position/peak found의 접근 가능성
  • Count 0~2를 셋팅으로 고정할지, Count 3까지 포함할지에 대한 현장 운영 기준
  • production stable 조건에서 필요한 연속 정상 poll 수 N과 허용 안정화 시간

최종 결론: 관측 데이터만 놓고 보면 6553.4 처리·캐시 방지·반복 관측 식별은 정상이다. 최종 수정은 6553.4를 지우거나 보간하는 방식이 아니라, under-range 상태를 보존하면서 금형 교체 phase를 별도로 부여하고, 미검증 물리 원인은 끝까지 미검증으로 유지하는 방식으로 진행해야 한다.

본 보고서의 정량값은 신규 CSV 3개 전수 분석 결과이며, 물리 원인에 관한 표현은 AMETEK 공식 문서와 현재 수집 필드가 허용하는 범위에서 후보 수준으로 제한했다.
