## QA와 표시 관찰 도구 검증

- 승인 정책을 제공하지 않은 기본 QA는 기존 comparator 요구를 유지한다. 새 경로는 정확한 정책 해시를 요구하며, 잘못된 타입/누락값/알람 ON/다른 build를 거부한다.
- 실제 metadata 확인은 `actual-disabled-scope.json`에 저장했다. 전체 one-command QA를 현장에서 실행한 결과로 표시하지 않았다.
- `approved_release_assessment.py`의 11개 시험, QA 전체 실행 흐름 5개 시험, 기존 종료/metadata 회귀 2개 시험이 모두 exit0이다. PowerShell의 제외 조건 32개 검사도 exit0이다.
- `observe_image_presentation.cjs`는 이미지 내용을 SHA256으로 연결하고 `presentationTime`을 별도 수집한다. 서버에 추가 이미지 HTTP 요청을 하지 않는다. 관찰 동안 `Response.arrayBuffer/blob`에 읽기 관찰을 붙이고 완료/제한시간에 원래 함수와 elementtiming 속성을 복원한다. 화면 초점이나 제품 갱신 타이머를 바꾸지 않는다.
- Chromium 148.0.7778.96 격리 fixture의 실제 6응답/6blob/6표시 연결·요청 수 불변·복원 및 모호한 대응/반복 source 시각/표시 시각 누락 거부를 확인했다. Node 시험 2개 exit0이다. headless 결과는 현장 표시 합격으로 사용하지 않는다.
- 브라우저 표시는 Windows 창 가려짐·모니터 출력·흰 화면 부재를 단독으로 증명하지 못한다. 관찰기 자체는 이 증거가 없으면 항상 INCOMPLETE이며 승격을 허용하지 않는다.

표시 계측의 기술 근거는 W3C의 작업 중인 [Element Timing 초안](https://w3c.github.io/element-timing/)과
[Paint Timing의 presentationTime 정의](https://w3c.github.io/paint-timing/#sec-paint-timing-mixin)다.
실제 운영 브라우저의 지원 여부와 계측 비용은 현장 준비 검사에서 추가 확인해야 한다.

중간 실패도 기록했다. PowerShell 시험의 비ASCII 기본 경로 문제는 명시적 경로 인자로 수정했다.
처음 재평가의 health INCOMPLETE는 전후 요청을 슬롯 표본으로 취급한 평가기 문제였고 R2에서 별도 검증으로 수정했다.
표시 관찰의 처음 방식은 브라우저가 응답 본문을 제공하지 않아 대응에 실패했다. 재요청으로 보충하지 않고,
앱이 이미 소비하는 바이트를 읽는 방식으로 수정했다. 최종 변경 상태의 관련 시험만 재실행했다.
기존 backend 모듈은 전역 `-W error`에서 종속 라이브러리 DeprecationWarning으로 import가 중단되어,
프로젝트의 실제 unittest 실행 방식과 같은 경고 설정·격리 APPDATA로 다시 실행해 통과했다.
